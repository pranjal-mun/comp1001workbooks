Linear search

1. A search returns a position

A search finds a target value in a list. Its result can tell us where the value occurs.

Membership gives a Boolean result. A position gives an index.

Our functions return a matching index, or -1 for no match.

index raises ValueError when no match exists.

2. Linear search checks each element

Linear search starts at index 0. It checks elements in order until it finds a match.

The list can be in any order. A match stops the search. A missing target requires a check of every element.

linear_search returns the first matching index. It returns -1 if the target is absent.

return i ends the function at the first match.

return -1 is outside the loop. It runs after every element fails to match.

The function reads the list. It leaves the list unchanged.

For an empty list, the function returns -1.

If each position is equally likely, a successful search averages (n + 1) / 2 checks.

Twice as many elements can require twice as many checks.

Binary search

5. Binary search removes half the range

Binary search requires data in ascending order. A middle value tells us which part can still contain the target.

A thick border marks the middle element. Faded elements are outside the current range.

binary_search returns a matching index in an ascending list. It returns -1 if no match exists. The two print lines at the end are for you to try.

low and high are inclusive bounds. If the target exists, it is within these bounds.

mid is the middle index. Floor division gives an integer index.

Each failed check removes mid and one side of the range. The loop ends when low > high.

Cost and recursion

8. The cost of binary search and the choice

Each failed middle check removes about half the remaining elements.

List lengthLinear maximumBinary maximum
10104
1,0001,00010
1,000,0001,000,00020
1,000,000,0001,000,000,00030

These counts measure visited elements. A binary iteration can use both == and < comparisons.

For n > 0, the binary maximum is ⌊log2 n⌋ + 1 element checks. Doubling the length adds one check to this maximum.

Use linear search for one search of unsorted data. Use binary search when the data is already sorted.

Many searches can justify sorting once. The number of searches must cover the sorting cost.

A very small list often needs only a simple linear search.

Sorting can change positions. A result for a sorted copy refers to that copy.

sorted creates an ascending copy. It leaves the original list unchanged. The code box repeats the two search functions so that it can run on its own.

Search results and linear search

Term or ruleMeaning
TargetThe value to find.
Successful resultAn index where the list contains the target.
Missing result-1. Check this before indexing the list.
Index 0A successful result. It is false in a Boolean test.
Linear searchVisit indices from 0 to len(values) - 1.
Match in a linear searchReturn the index immediately. This gives the first match.
No matchReturn -1 after the loop.
Data orderLinear search works with any order.
Element checksAt most n. An empty list needs zero checks.
Input listBoth search functions leave it unchanged.

Binary search and the choice

RuleMeaning
PreconditionThe list is in ascending order. Duplicates are allowed.
Initial boundslow = 0, high = len(values) - 1.
Nonempty rangelow <= high. Both bounds are inclusive.
Middle indexmid = (low + high) // 2.
Target is largerSet low = mid + 1.
Target is smallerSet high = mid - 1.
ResultReturn mid for a match, or -1 for an empty range.
Recursive versionPass the new bounds. Return the result of the recursive call.
Maximum checks⌊log2 n⌋ + 1 for n > 0. Zero for an empty list.
Practical choiceOne unsorted search favors linear search. Repeated searches can justify sorting once.

A binary result can be any match. A result after sorting refers to the sorted order.
