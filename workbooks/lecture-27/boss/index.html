Linear and binary search

How bosses work

These problems use linear and binary search from Lecture 27:

  • a linear pass that visits every element, or stops at the first match
  • the sorted-data precondition of binary search
  • counting the element checks that each search makes

They use only what Lectures 4 to 27 covered:

  • input() with int() and float(), split(), and blank input lines
  • f-strings with field widths such as :7d and :>7
  • while and for loops, range, and if statements
  • lists, indexes, and functions that return a value

Each problem names the functions to write. Write the rest of the program at the top level, after the functions. Each problem lists the rules its checker enforces. A program that prints the right answer but breaks a rule does not pass. Term tests and the final exam have questions of this kind, and you write the code in PyLab there as well.

Every problem reads its values with a plain input() that shows no prompt, so the output is only what your program prints. Check runs your program several times and types a different sequence of answers each time. Every run must print exactly what the examples show. Check also calls your functions directly with other lists.

Defeat a boss and its marker on the workbooks page is crossed off.

Press ▶ Run to try your program and Check to fight the boss. The bosses get harder from 👹 to 💀 and are worth 10, 15, 20, and 25 XP.

👹 Boss 1: Count readings within limits

Write a program that reads sensor readings until a blank line. Read one number per line. The blank line ends the readings. Then read a lower limit and an upper limit on separate lines. Print how many readings are at least the lower limit and less than the upper limit.

  • Write count_in_range(values, low, high) to return the count.
  • Keep the input list unchanged. Count repeated values separately.
  • Use one linear pass that counts matches instead of stopping.
  • An empty list or a range containing no readings has count 0.
Example 1
Input:
1.5
4
4
9
(blank line)
4
9
Output:
Count: 2
Explanation:
Both readings equal to 4 are included. The reading 9 is excluded.
Example 2
Input:
(blank line)
0
10
Output:
Count: 0
Explanation:
No readings were entered.
Example 3
Input:
2
5
(blank line)
7
8
Output:
Count: 0
Explanation:
Neither reading is within the limits.
Constraints
  • Readings and limits are valid numbers from -1000 through 1000.
  • The lower limit is at most the upper limit.
  • Use a loop and a counter. Do not use count() or a comprehension with len.
  • Read input without prompts. Print the count after Count:.

To enter the blank line, press Enter without typing anything. Check types each of these sequences. The examples are the first three rows.

Rules the checker enforces
  • Define count_in_range(values, low, high) with three parameters. It returns the count and keeps its input unchanged.
  • In count_in_range, use a loop and a counter.
  • Do not use count() or a comprehension.

👾 Boss 2: Check the order before searching

Write a program that reads numbers until a blank line. Read one number per line. Report whether their order meets a binary search precondition. Ascending order allows equal neighbors and never decreases. Descending order allows equal neighbors and never increases.

  • Write is_sorted(values). Return True for ascending or descending order, and False otherwise.
  • Keep the input list unchanged. Empty and one-element lists are sorted.
  • Print Ascending binary search can be used when ascending order holds.
  • Otherwise, print Descending binary search can be used when descending order holds.
  • Otherwise, print Binary search cannot be used.
  • If both orders hold, use the ascending message. A descending search must reverse the direction of the bound updates.
Example 1
Input:
18
12
12
3
(blank line)
Output:
Descending binary search can be used
Explanation:
The values never increase. Equal neighbors are allowed.
Example 2
Input:
(blank line)
Output:
Ascending binary search can be used
Explanation:
An empty list satisfies both orders. The ascending message has priority.
Example 3
Input:
3
8
5
(blank line)
Output:
Binary search cannot be used
Explanation:
The values increase and then decrease.
Constraints
  • Each value is a valid number from -1000 through 1000.
  • Check neighboring values with loops. Do not sort the input.
  • Use is_sorted in the main program. Read input without prompts.

  • Define is_sorted(values) with one parameter. It returns True or False and keeps its input unchanged.
  • In is_sorted, compare neighboring values with a loop. Do not use sort or sorted.
  • Call is_sorted in the main program.

🐉 Boss 3: Compare the work of two searches

Write a program that compares linear and binary search on the same ascending list. Build the multiples of 3 from 3 through 300 with list(range(3, 301, 3)). Read integer targets until a blank line. Print one table row per target.

  • Write linear_checks(values, target) and binary_checks(values, target).
  • Use the searches from this lecture with counters added. Keep the input list unchanged.
  • Each function returns only its number of element checks. Count an element once when the search visits its index.
  • Decide presence with a separate call to binary_search or with in.
  • Print the target, presence, linear count, and binary count in that order.
  • Use four right-aligned columns of width 7, separated by one space. Print the header even when there are no targets.
  • Think about why the binary count stays at most 7 for this list of 100 elements. The model answer explains it.
Example 1
Input:
3
300
4
303
(blank line)
Output:
 Target Present  Linear  Binary
      3    True       1       6
    300    True     100       7
      4   False     100       7
    303   False     100       7
Explanation:
The first target stops linear search immediately. Each absent target requires all 100 linear checks.
Example 2
Input:
(blank line)
Output:
 Target Present  Linear  Binary
Explanation:
There are no targets, so only the header is printed.
Constraints
  • Each target is an integer from -1000 through 1000.
  • Use for for linear search and while for binary search.
  • A match ends the counting function with return. Do not return an index as well.
  • Use fixed-width formatting. Read input without prompts.

💀 Boss 4: Find a consecutive pattern

Write a program that reads two lines of integers separated by spaces. The first line is the larger list. The second line is the smaller list. Use split() to read each line. A sublist is a list whose elements appear next to each other, in the same order, inside another list.

  • Write is_sublist(larger, smaller) to return whether the smaller list is a sublist.
  • Write sublist_start(larger, smaller) to return its first start index, or -1 when absent.
  • Keep both input lists unchanged. Neither function returns two values.
  • Check start positions from 0 through len(larger) - len(smaller) in order. Compare elements one at a time.
  • The empty list is a sublist of every list, at index 0. A list is a sublist of itself.
  • Print Found: and the Boolean result. When found, print Start: and the first start index on the next line.
Example 1
Input:
8 3 8 3 6
8 3 6
Output:
Found: True
Start: 2
Explanation:
The first candidate fails at its third element. The pattern begins at index 2.
Example 2
Input:
5 9
(blank line)
Output:
Found: True
Start: 0
Explanation:
The empty pattern starts at index 0.
Example 3
Input:
2 4 7
2 7
Output:
Found: False
Explanation:
The values occur in order, but they are not next to each other.
Constraints
  • Each line contains zero through 100 integers from -1000 through 1000.
  • A blank line represents an empty list. The smaller list may be longer than the larger list.
  • Use loops and element comparisons. Do not compare slices or whole lists with ==.
  • Call both functions in the main program. Read input without prompts.

  • Call both functions in the main program.
