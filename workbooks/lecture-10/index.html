2. Multiple Alternatives

The elif Keyword

Some decisions choose one result from several alternatives. A grade belongs to one band: A, B, C, D, or F. Deep nesting can express this choice, but every extra level shifts the code farther right. Python uses elif, short for “else if,” to keep the alternatives aligned.

An if/elif/else chain has one starting if, zero or more elif branches, and an optional final else. All headers in the chain line up.

The First True Condition Wins

Python checks a chain from top to bottom. It runs the block for the first true condition and then skips the rest of the chain.

Although score >= 70 is also true, Python never tests it because the first branch already won.

Redundant Conditions

In the correct grade chain, reaching score >= 70 means score >= 80 has already failed. Python therefore already knows the score is below 80.

Prefer the shorter condition:

elif score >= 70:
    grade = "B"

There is no need to test the upper boundary again. The earlier branch already ruled it out. Removing a redundant test makes the chain easier to read and gives you fewer places to make a boundary mistake.

The Final else

The final else runs only when every earlier condition is false. It has no condition because it catches all remaining values.

The catch-all ensures that label receives a value for every possible temperature. Without it, a value below 10 would leave label unassigned, and a later use could cause a NameError.

3. Choosing a Decision Structure

An elif Chain Versus Separate ifs

An elif chain stops after one branch wins. Separate if statements are independent, so Python tests every one.

Both conditions are true. The second assignment overwrites the first. When the cases are alternatives, use one chain so only one branch runs.

Separate if statements are correct when more than one result may apply.

Here both messages are useful, so the questions are independent.

Putting It All Together

The final program combines a chain and a nested decision. It calculates an admission price from three pieces of information:

  • A visitor younger than 13 pays a base price of $8.
  • A visitor from 13 through 64 pays a base price of $14.
  • A visitor 65 or older pays a base price of $10.
  • A member receives a $3 discount after at least five visits and a $1 discount otherwise.
  • A non-member receives no discount.

Assume that the user enters a valid non-negative age and visit count, and enters yes or no for membership. Input validation belongs to the next lecture.

Step 1: Choose One Base Price

The age bands are alternatives, so use one chain. The tests use increasing upper limits. If age < 13 fails, the next branch already knows the visitor is at least 13.

if age < 13:
    base_price = 8
elif age < 65:
    base_price = 14
else:
    base_price = 10

Step 2: Decide the Member Discount

The visit count matters only for members, so put that decision inside the member branch.

if member == "yes":
    if visits >= 5:
        discount = 3
    else:
        discount = 1
else:
    discount = 0

The two decisions assign base_price and discount. The final calculation is shared by every path, so it belongs after both decisions.
