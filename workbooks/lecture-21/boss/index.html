How bosses work

These problems use recursion from Lecture 21:

  • a base case that returns without another call
  • a recursive case that makes one call on a smaller problem
  • a return value built from the answer of that call

They use only what Lectures 4 to 21 covered:

  • input() with int() and float()
  • arithmetic, including // and %
  • comparisons and if statements
  • functions, default parameter values, main(), and the __name__ guard

Each problem lists the rules its checker enforces. A program that prints the right answer but breaks a rule does not pass. Check also calls your functions directly with more values and compares what they return. Term tests and the final exam have questions of this kind, and you write the code in PyLab there as well.

Every problem reads its values with a plain input() that shows no prompt, so the output is only what your program prints. Check runs your program several times and types a different sequence of answers each time. Every run must print exactly what the examples show.

Each problem also asks you to trace or explain your program. Those parts are under the code box. Check grades only the program.

Defeat a boss and its marker on the workbooks page is crossed off.

Press ▶ Run to try your program and Check to fight the boss. The bosses get harder from 👹 to 🐉 and are worth 10, 15, and 20 XP.

👹 Boss 1: Common factor finder

Write the function gcd(a, b) and a program that uses it. The function returns the greatest common divisor of two integers. A divisor divides a number with no remainder. The greatest common divisor is the largest positive integer that divides both numbers. Every positive integer divides zero.

Use these rules, called Euclid's algorithm:

  • If b == 0, return a.
  • Otherwise, find the remainder a % b.
  • Return the result of gcd(b, a % b).

Write these functions:

  1. gcd(a, b) returns the greatest common divisor using the rules above.
  2. main() reads a, then b, on separate lines. It prints GCD: followed by the result.

Trace gcd(48, 18) in the table. Record each call and its returned value. Explain why a positive second argument gets closer to zero.

Example 1
Input:
48
18
Output:
GCD: 6
Explanation:
6 is the largest positive integer that divides both 48 and 18.
Example 2
Input:
7
0
Output:
GCD: 7
Explanation:
The second argument is zero, so the first call returns 7.
Constraints
  • a is an integer from 1 through 10000.
  • b is an integer from 0 through 10000.
  • Use recursion, no loops, and one recursive call in the recursive case.
  • Use b == 0 as the base case.
  • Use the two required functions and the standard guard.

👾 Boss 2: Total until blank

Write the function read_total() and a program that uses it. The function reads numbers, one per line, until it reads a blank line. It returns their total as a floating-point number. A blank line is a sentinel: a special input that ends the reading.

Follow these rules:

  • Each call reads exactly one line.
  • A blank line returns 0.0 without another call.
  • Otherwise, convert the line with float.
  • Add that number to the total returned by one recursive call.
  • Zero is a number to include. It does not end the input.
  • A negative number reduces the total.

Write these functions:

  1. read_total() takes no parameters and returns the total. It does not print.
  2. main() calls read_total() once. It prints Total: followed by the result to two decimal places.

For the first example, record the line read by each call. Explain which call supplies the first returned answer. Explain why a new call does not erase the number read by its caller.

Example 1
Input:
4.5
0
-1.25
(blank line)
Output:
Total: 3.25
Explanation:
The blank fourth line ends the input. The total is 4.5 plus 0 minus 1.25.
Example 2
Input:
(blank line)
Output:
Total: 0.00
Explanation:
The first line is blank, so no numbers are added.
Constraints
  • There are 0 through 80 number lines, followed by a blank line.
  • Each number is from −1000 through 1000 and is valid input for float.
  • Use recursion and no loops.
  • read_total must have no parameters.
  • Keep each number in its own call. Return the total from each call.
  • Use the two required functions and the standard guard.

The program reads one number per line with no prompt. To type the blank line, press Enter without typing anything.

🐉 Boss 3: Square root by better guesses

Write the function square_root(n, guess=1.0) and a program that uses it. The function returns an approximation to the positive square root of n. The square root is the positive number whose square equals n. The parameter guess holds the current approximation.

Use these rules:

  • Give guess the default value 1.0. Give n no default.
  • Find the error with abs(guess * guess - n). The function abs returns the size of a number without its sign.
  • Return guess when the error is at most 1e-12, which means 10−12.
  • This error allowance is called the tolerance.
  • Otherwise, calculate (guess + n / guess) / 2.
  • Make one recursive call with the same n and the new guess. Return its answer.

Write these functions:

  1. square_root(n, guess=1.0) implements the rules above.
  2. main() reads n and calls square_root(n) with one argument. It prints Root: followed by the answer to six decimal places.

After testing the program, change only the tolerance to 1e-30 and try square_root(2). Record what happens. Explain why a base case can exist even when the calculation cannot reach it.

Example 1
Input:
2
Output:
Root: 1.414214
Explanation:
The returned guess has a squared error of at most 1e-12.
Example 2
Input:
1
Output:
Root: 1.000000
Explanation:
The default guess already has zero error, so the first call returns.
Constraints
  • n is a number from 1 through 100, including both endpoints.
  • An explicitly supplied guess is a positive number.
  • Use recursion, no loops, and one recursive call in the recursive case.
  • Use the default guess in main.
  • Use 1e-12 in the submitted program. Test 1e-30 in a separate copy.
  • Use the two required functions and the standard guard.
