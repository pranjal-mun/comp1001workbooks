How bosses work

A boss problem is bigger than the practice questions in the workbook, but it only uses what Lecture 4 covered: assignment and reassignment, adding with +, the four types and type(), print() with several values, readable names, constants, and comments. There are no hints in the code box. Plan the steps on paper first, then write the program. Each problem lists the rules its checker enforces. A program that prints the right answer but breaks a rule does not pass. Term tests and the final exam have questions of this kind, and you write the code in PyLab there as well.

Each problem starts with its values already assigned at the top of the program. Keep those lines exactly as they are: Check runs your program several times, swapping in different values each time, and every run must print exactly what the table shows. Defeat a boss and its marker on the workbooks page is crossed off.

Press ▶ Run to try your program with the given values and Check to fight the boss. The bosses get harder from 👹 to 💀 and are worth 10, 15, 20, and 25 XP.

👹 Boss 1: Trade Places

Oliver is a seven-year-old black toy poodle, and Sabina is a cat. Their favourite spots are stored as text in oliver and sabina.

Today they want to switch spots. Swap the values so that oliver gets Sabina's original spot and sabina gets Oliver's original spot. Then print both spots on one line, with Oliver's first.

Be careful: once you do oliver = sabina, Oliver's old value is lost. You will need a third variable to save it first. Three assignments do the whole job.

oliver, sabinaOutput
'sofa', 'basket'basket sofa
'bed', 'windowsill'windowsill bed
'porch', 'kitchen'kitchen porch
'rug', 'rug'rug rug
Rules the checker enforces
  • Use a third variable during the swap. Do not type the spot values again.
  • Use one assignment per statement. Do not use a, b = b, a (that form comes later in the course).
  • No +=.
  • Print both spots on one line using one print().

Keep oliver = 'sofa' and sabina = 'basket' unchanged. The checker will replace them with the other test values.

👾 Boss 2: Filling EN2043

COMP 1001 meets in EN2043. The 120 students arrive in three groups.

The program starts with seated = 0, and the three group sizes are stored in group_1, group_2, and group_3.

After each group arrives, add that group to seated and print the new total in exactly this format:

After group 1: 40
After group 2: 65
After group 3: 120

Keep using the same variable, seated. Each time, take its current value, add the next group, and store the result back into seated. Each print() shows a text label followed by the current total.

A negative group means some students left.

group_1, group_2, group_3Output
40, 25, 55After group 1: 40 / After group 2: 65 / After group 3: 120
0, 60, 60After group 1: 0 / After group 2: 60 / After group 3: 120
50, -10, 80After group 1: 50 / After group 2: 40 / After group 3: 120
120, 0, 0After group 1: 120 / After group 2: 120 / After group 3: 120
Rules the checker enforces
  • Update seated three times using seated = seated + ....
  • No +=.
  • Print exactly three lines in the format shown.
  • seated must still be an int at the end.

Keep the four assignment lines unchanged. The checker will replace the group sizes.

🐉 Boss 3: Vet Record

Oliver's vet record stores four values: pet, age, weight (in kilograms), and vaccinated.

Print each value followed by its type, one per line, in this order:

Oliver <class 'str'>
7 <class 'int'>
3.5 <class 'float'>
True <class 'bool'>

Do not assume the types will always stay the same. The checker will change both the values and their types. For example, in one run the record is Sabina's, age becomes the text 'unknown', and weight becomes the whole number 4.

The type belongs to the value, not the name, so your program must use type() to find the type each time it runs.

Rules the checker enforces
  • Use type() to get each type while the program runs.
  • Do not write class, int, float, str, or bool directly in your code.
  • Print the variables, not copied literal values. A run that changes a value must change the output.
  • Print exactly four lines in the order given.

Keep the four assignment lines unchanged. The checker will replace the record values.

💀 Boss 4: Repair the Course Record

This boss already has some code, but the code is broken.

It is supposed to print the lecture room, the course, the instructor, and the number of students after one more registers:

EN2043 COMP 1001 Pranjal Patra 120

There are five problems in the starter code. They are all based on Lecture 4 topics: invalid variable names, a reserved word being used as a variable name, a value that stays fixed all term but is not written as a constant, and inconsistent spelling of a variable name.

Run the program, read the error, fix one thing at a time, and keep going until it prints the line above.

You can rename variables, but keep the same meaning: the room, the course code, the instructor, and the number of students should each have their own variable.

studentsOutput
119EN2043 COMP 1001 Pranjal Patra 120
0EN2043 COMP 1001 Pranjal Patra 1
57EN2043 COMP 1001 Pranjal Patra 58
Rules the checker enforces
  • Use lower_case_with_underscores for variable names, with no single-letter names.
  • Store the room in an ALL_CAPS constant and keep its value as 'EN2043'.
  • Keep the update as students = students + 1. Fix the spelling rather than typing the final number.
  • No +=.
  • Include one comment beginning with # that explains a choice.

Keep students = 119 unchanged. The checker will replace that value for the other tests.
