How bosses work

A boss problem is bigger than the practice questions in the workbook, but it only uses what Lecture 4 covered: assignment and reassignment, adding with +, the four types and type(), print() with several values, readable names, constants, and comments. Plan the steps on paper first, then write the program. Each problem lists the rules its checker enforces. A program that prints the right answer but breaks a rule does not pass. Term tests and the final exam have questions of this kind, and you write the code in PyLab there as well.

Each problem starts with its values already assigned at the top of the program. Keep those lines exactly as they are: Check runs your program several times, swapping in different values each time, and every run must print exactly what the table shows. Defeat a boss and its marker on the workbooks page is crossed off.

Press ▶ Run to try your program with the given values and Check to fight the boss. The bosses get harder from 👹 to 💀 and are worth 10, 15, 20, and 25 XP.

👹 Boss 1: Trade Places

Oliver is a seven-year-old black toy poodle and Sabina is a cat. You are given their favourite spots as text in oliver and sabina. Swap the two values so that oliver holds Sabina's original spot and sabina holds Oliver's, then print both spots on one line, Oliver's first.

Once you do oliver = sabina, Oliver's old value is gone. Save it in a third variable first. Three assignments do the whole job.

Example 1
Input: oliver = 'sofa', sabina = 'basket'
Output: basket sofa
Explanation: Oliver moves to the basket and Sabina to the sofa.
Example 2
Input: oliver = 'rug', sabina = 'rug'
Output: rug rug
Explanation: both spots are the same, so the swap changes nothing you can see.
Constraints
  • Each spot is a word with no spaces.

The program starts with the two assignments already written.

oliver, sabinaOutput
'sofa', 'basket'basket sofa
'bed', 'windowsill'windowsill bed
'porch', 'kitchen'kitchen porch
'rug', 'rug'rug rug
Rules the checker enforces
  • Use a third variable during the swap. Do not type the spot values again.
  • One assignment per statement. No a, b = b, a (that form comes later in the course).
  • No +=.
  • Print both spots on one line with one print().

Keep oliver = 'sofa' and sabina = 'basket' unchanged. The checker will replace them with the other values.

👾 Boss 2: Filling EN2043

COMP 1001 meets in EN2043 and the 120 students arrive in three groups. You are given the three group sizes, group_1, group_2, and group_3, and a count seated that starts at 0. Seat each group in turn: add it to seated and print the new total after each group. A negative group means some students left.

Keep using the same variable. Each time, take the current value of seated, add the next group, and store the result back into seated. Each print() shows a text label followed by the current total.

Example 1
Input: group_1 = 40, group_2 = 25, group_3 = 55
Output:
After group 1: 40
After group 2: 65
After group 3: 120
Explanation: 0 + 40 is 40, then 40 + 25 is 65, then 65 + 55 is 120.
Example 2
Input: group_1 = 50, group_2 = -10, group_3 = 80
Output:
After group 1: 50
After group 2: 40
After group 3: 120
Explanation: ten students left after the first group, so the count goes down before the last group arrives.
Constraints
  • -120 <= group_1, group_2, group_3 <= 120
  • seated starts at 0.

The program starts with the four assignments already written.

group_1, group_2, group_3Output
40, 25, 55After group 1: 40 / After group 2: 65 / After group 3: 120
0, 60, 60After group 1: 0 / After group 2: 60 / After group 3: 120
50, -10, 80After group 1: 50 / After group 2: 40 / After group 3: 120
120, 0, 0After group 1: 120 / After group 2: 120 / After group 3: 120
Rules the checker enforces
  • Update seated three times in the form seated = seated + ....
  • No +=.
  • Print exactly three lines in the format shown.
  • seated must still be an int at the end.

Keep the four assignment lines unchanged. The checker will replace the group sizes.

🐉 Boss 3: Vet Record

You are given four values from Oliver's vet record: pet, age, weight in kilograms, and vaccinated. Print each value followed by its type, one per line, in that order.

The checker changes both the values and their types between runs, so your program must ask Python with type() each time it runs. The type belongs to the value, not the name.

Example 1
Input: pet = 'Oliver', age = 7, weight = 3.5, vaccinated = True
Output:
Oliver <class 'str'>
7 <class 'int'>
3.5 <class 'float'>
True <class 'bool'>
Explanation: each line is the value, a space, and what type() reports for it.
Example 2
Input: pet = 'Sabina', age = 'unknown', weight = 4, vaccinated = True
Output:
Sabina <class 'str'>
unknown <class 'str'>
4 <class 'int'>
True <class 'bool'>
Explanation: this time age is text and weight is a whole number, so the types change with the values.
Constraints
  • Each value is an int, a float, a str, or a bool.

The program starts with the four assignments already written.

Runpetageweightvaccinated

Sabina, age unknown'Sabina''unknown'4True
Half years, text flag'Oliver'7.53.5'yes'

Rules the checker enforces
  • Use type() to get each type while the program runs.
  • Do not write class, int, float, str, or bool in your code (comments are fine).
  • Print the variables, not copied values. A run that changes a value must change the output.
  • Print exactly four lines in the order given.

Keep the four assignment lines unchanged. The checker will replace the record values.

💀 Boss 4: Repair the Course Record

You are given a broken program. It is meant to print the lecture room, the course, the instructor, and the number of students after one more registers, all on one line. There are five problems in it, all from Lecture 4: invalid variable names, a reserved word used as a variable name, a value that stays fixed all term but is not written as a constant, and inconsistent spelling of a variable name.

Run the program, read the error, fix one thing at a time, and keep going until it prints the right line. You can rename variables, but keep the same meaning: the room, the course code, the instructor, and the number of students each get their own variable.

Example 1
Input: students = 119
Output: EN2043 COMP 1001 Pranjal Patra 120
Explanation: one more student registers, so 119 becomes 120.
Example 2
Input: students = 0
Output: EN2043 COMP 1001 Pranjal Patra 1
Constraints
  • 0 <= students <= 500
  • The room, course code, and instructor never change.
studentsOutput
119EN2043 COMP 1001 Pranjal Patra 120
0EN2043 COMP 1001 Pranjal Patra 1
57EN2043 COMP 1001 Pranjal Patra 58
Rules the checker enforces
  • Use lower_case_with_underscores for variable names, with no single-letter names.
  • Store the room in an ALL_CAPS constant and keep its value as 'EN2043'.
  • Keep the update as students = students + 1. Fix the spelling rather than typing the final number.
  • No +=.
  • Include one comment beginning with # that explains a choice.

Keep students = 119 unchanged. The checker will replace that value for the other tests.
