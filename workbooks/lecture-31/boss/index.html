Input validation and robust programs

Pranjal Patra

How bosses work

These problems use validation functions and loops that handle bad input:

  • a function that converts and checks a value, and raises ValueError
  • a validation loop that asks again until the input is valid
  • a loop that reads until a blank line, skips bad entries, and handles the case with no valid values

They use only what Lectures 4 to 31 covered:

  • input() with int(), and a blank line that ends the input
  • f-strings such as :.2f, and the string methods split, strip and lower
  • if tests, while loops, lists, the list method index, functions with docstrings, and try/except

Each problem lists the rules its checker enforces. A program that prints the right answer but breaks a rule does not pass. The final exam has questions of this kind, and you write the code in PyLab there as well.

Every problem reads its values with a plain input() that shows no prompt, so the output is only what your program prints. Check runs your program several times and types a different sequence of answers each time. Every run must print exactly what the table shows. The checker also calls your functions directly, so each function must return the values and raise the exceptions that the problem names.

Defeat a boss and its marker on the workbooks page is crossed off.

Press ▶ Run to try your program and Check to fight the boss. The bosses get harder from 👹 to 👾 and are worth 10 and 15 XP.

👹 Boss 1: Shipping cost

Write a program that reads the number of items in an order and prints the shipping cost.

  • to_items(text) takes a string and returns the number of items as a whole number. It raises ValueError if the conversion fails.
  • For an item count below 1, to_items raises ValueError("items must be at least 1").
  • shipping_cost(items) takes a valid item count and returns the cost in dollars. It raises no exception for a valid count.
  • Shipping costs $10.95 for the first item and $2.95 for each item after it.
  • main() reads item counts until one is valid. For each bad input, it prints Enter a whole number of at least 1.
  • For a valid count, print Shipping: $ followed by the cost with two decimal places.
Example 1
Input:
3
Output:
Shipping: $16.85
Explanation:
The order has one item at $10.95 and two at $2.95 each.
Example 2
Input:
0
two
1
Output:
Enter a whole number of at least 1.
Enter a whole number of at least 1.
Shipping: $10.95
Explanation:
The first valid input is 1, the smallest allowed count.
Constraints
  • A valid count is a whole number of at least 1. The input ends with a valid count.
  • Use input() with no prompt. Convert the text with int.
  • Raise and handle ValueError. Use no bare except.
  • Use no input or print in the helper functions.
  • Write a docstring for each function. Call main() on the last line.

  • Ask again in a while loop. Do not use a bare except or except Exception.

👾 Boss 2: Checking dates

Write a program that checks dates. Each input line contains one entry. A blank line ends the input.

  • days_in_month(name) takes a month name in any case and returns the number of days. Raise ValueError("unknown month") for an unknown name.
  • check_date(line) takes a line of text and returns the day as a whole number.
  • Raise ValueError("expected month and day") unless the line has exactly two parts.
  • The first part is the month. The second part is the day. Let int raise ValueError if the day cannot be converted.
  • Raise ValueError("day out of range") if the day is outside the range for that month.
  • main() reads each line and removes spaces from its ends before checking it.
  • For a valid entry, print Valid: followed by the stripped line.
  • For a bad entry, print Rejected: followed by the stripped line, a space and the exception message in parentheses. Then read the next line.
  • At the end, print Valid dates: followed by the count. If the count is zero, print No valid dates. instead.
Example 1
Input:
March 14
february 29
February 30
Smarch 3
March 14.5
(blank line)
Output:
Valid: March 14
Valid: february 29
Rejected: February 30 (day out of range)
Rejected: Smarch 3 (unknown month)
Rejected: March 14.5 (invalid literal for int() with base 10: '14.5')
Valid dates: 2
Explanation:
February allows day 29. A day with a decimal point fails the conversion.
Example 2
Input:
(blank line)
Output:
No valid dates.
Explanation:
The first line ends the input before the program counts any dates.
Constraints
  • A valid entry has a full month name and a day separated by spaces.
  • The day must be a whole number from 1 to the number of days in the month.
  • February has 29 days.
  • Use input() with no prompt. Use the two lists in the starter code.
  • Use split to get the parts and int to convert the day.
  • Raise ValueError and handle it with except ValueError as err. Use no bare except.
  • Use no input or print in the helper functions.
  • Write a docstring for each function. Call main() on the last line.
