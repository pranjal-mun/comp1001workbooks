2. Frame cost and the problem's shape

For input 4, both factorial versions perform four multiplications. The recursive version also makes calls for 3, 2, 1, and 0. Each function call needs a frame and call handling. A loop repeats inside its existing frame.

For this recursive version, peak depth is n + 1. Large inputs can hit Python's depth limit.

A running total changes after each number. A counter increases until it reaches a limit. A loop usually expresses these repeated updates directly.

Repeated work

3. Naive Fibonacci and repeated work

fib(n) returns Fibonacci number n. Here, fib(0) = 0 and fib(1) = 1. Each later number is the sum of the previous two. Assume a nonnegative integer input.

fib(4) needs fib(3) and fib(2). But fib(3) also needs fib(2). Both calls compute that answer from scratch. This direct translation of the formula is called the naive recursive version.

In the call tree for fib(4), two branches each compute fib(2) and get 1. Each branch also makes its own calls to fib(1) and fib(0). Nine calls produce the final answer, 3. The repeated branch includes its own smaller calls.

To find a Fibonacci number, keep the current value and the next one. With a = 2 and b = 3, save next_value = 5. Then shift to a = 3 and b = 5.

Start with a = 0 and b = 1. After n updates, a is Fibonacci number n. Save the sum before changing either old value. Each update uses the values from the previous update.

Towers of Hanoi

6. Towers of Hanoi and the three-disc moves

Move the three discs from peg A to peg C. Peg B is available as a spare. Move one disc at a time. Take only the top disc from a peg. A larger disc must never sit on a smaller disc. Disc 1 is the smallest.

To move three discs from A to C, first move the top two out of the way:

  1. Move the top two discs from A to B.
  2. Move disc 3 from A to C.
  3. Move the top two discs from B to C.

Each two-disc transfer is the same task with one fewer disc.

The top two discs must reach B before disc 3 can move to C. The first three moves are:

  1. Move disc 1 from A to C.
  2. Move disc 2 from A to B.
  3. Move disc 1 from C to B.

Move disc 3 to C. Then transfer the two-disc tower from B to C. The remaining moves are:

  1. Move disc 3 from A to C.
  2. Move disc 1 from B to A.
  3. Move disc 2 from B to C.
  4. Move disc 1 from A to C.

7. Reading and tracing the Hanoi function

hanoi(n, source, target, spare) prints the moves for n discs. It moves the top n discs from source to target, using spare.

  1. The first call puts the smaller tower on the spare peg.
  2. The print moves the largest disc of this tower.
  3. The second call moves the smaller tower to the target.

The peg roles change on each call. For the outer call, A is the source, C the target, and B the spare.

8. Counting the Hanoi moves

Let M(n) be the number of moves for n discs. Move the top n − 1 discs, move the largest disc, then move the smaller tower again. The two smaller transfers each need M(n − 1) moves. Moving the largest disc needs one move.

M(0) = 0      M(n) = 2M(n − 1) + 1

Discs012345
Moves01371531

The count doubles, then gains one. This gives M(n) = 2n − 1, written 2**n - 1 in Python. Every disc in the smaller tower must leave the source before the largest disc moves.

Choosing an approach

9. Choosing an approach

Start with the clearest correct description of the task.

  • Usually choose a loop to repeat an update to a few values.
  • Consider recursion to solve the same task on smaller parts.

Before choosing recursion, estimate the maximum depth. Check whether the same smaller problem repeats. For Hanoi, recursion makes the moves easy to describe. The required number of moves still grows as 2n − 1.

Final review

Loops, calls and repeated work

TopicWhat to remember
Same problemA loop and recursion can return the same answer. Compare clarity and work.
Simple accumulationA loop updates its local total or product inside one function frame.
Recursive costEach call adds a frame and call handling. Peak depth counts unfinished calls.
Factorial examplesBoth do n multiplications. Recursion peaks at n + 1 frames. The loop uses one.
Naive FibonacciThe same inputs appear in different branches. Each call computes its answer again.
Work versus depthTotal calls measure repeated work. Peak depth measures the longest active path.
Fibonacci loopKeep consecutive values. Save their sum before shifting them forward. Our version makes n updates.

Hanoi and the final choice

TopicWhat to remember
Hanoi rulesMove one top disc at a time. Never put a larger disc on a smaller one.
Recursive transferMove n − 1 discs to the spare peg. Move the largest disc to the target. Move the smaller tower onto it.
Peg rolesRead each call as n, source, target, spare. The roles change in the two recursive calls.
Move countM(0) = 0 and M(n) = 2M(n − 1) + 1. Therefore M(n) = 2n − 1.
Counting versus movingA count function can reuse one smaller count. Printing a solution must produce every move.
Recursion fitsThe task has a clear smaller version and the depth and total work stay reasonable.
A loop fitsThe task is a sequence of updates to a few values. It avoids a chain of unfinished function calls.
