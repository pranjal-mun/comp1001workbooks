def read_int_between(prompt, low, high):
    value = int(input(prompt))

Local names

5. Local names and returned values

Scope is the region of a program where a name is visible.

The parameters width, height, and the local variable area belong to the helper. After it returns, main stores the value 12 in its own result.

def compute():
    temp = 42
    return temp

def main():
    result = compute()
    print(result)
    print(temp)

if __name__ == "__main__":
    main()

42 prints first. The next print raises NameError: main cannot use the helper's temp. When the helper's call ends, its local bindings end. The returned value can remain available through the caller's name.

6. Separate calls and assignment paths

double finishes before square starts. Each call has its own temp, with no interference.

An if or loop does not create a separate local scope. The assignments have run, so these names have values. If the loop ran zero times, those assignments would not happen. An if also needs its assignment path to run before a new local can be read.

Globals and shadowing

7. Reading a global name

Output: 18.0

A name assigned at the file's top level is global. The helper reads it when it has no local binding for that name. Changing it can change the result without changing the call.

8. Shadowing and assignment

Output: 5, then 100.

Inside show_total, the parameter hides the global name. It does not change the global value. The two bindings are separate.

count = 0

def increment():
    count = count + 1

def main():
    increment()

if __name__ == "__main__":
    main()
UnboundLocalError

The assignment makes count local to increment throughout its body. The right-hand side tries to read that local before it has a value. Python does not fall back to the global zero. Scope tells us which binding a name refers to. A local value is usable only after an assignment has actually run, or after an argument has supplied a parameter's value.

9. Explicit input and a return

Output: 1

main calls increment(0), which returns 1. main owns its changing count and stores the returned value. The helper can also be tested directly: increment(10) returns 11.

10. Fixed constants

Output: 180

Use uppercase names for values assigned once and kept fixed. Examples: SECONDS_PER_MINUTE, MAX_ATTEMPTS. Uppercase is a convention, not protection: Python still permits reassignment. The course permits genuine constants at global scope and keeps changing program state local.

Final review

Reuse and stepwise refinement

Reusable functionExtract repeated work. Make values that vary into parameters, such as a prompt and its allowed range.
Clear inputsSupply changing data as arguments. Calculation helpers return results. Make prompting or printing an explicit input/output helper's job.
RefinementBreak the problem into tasks. Refine each unclear task into smaller steps until its implementation is straightforward.
Top-down designSketch main() using meaningful helper calls first. Decide what each helper receives and produces, then implement the helpers.
Stopping and testsStop at a coherent task with a clear body. Test each helper independently, including boundaries, then check the complete program.

Scope, shadowing, and globals

Local namesParameters and names assigned in a function belong to that call. Other functions cannot read them just because they called it.
Scope and valuesA local binding applies throughout the function. Read its value only after it has been assigned. An if or loop does not create a separate local scope.
Global namesAssigned at the file's top level. A function can read them if it has no local binding of that name. Avoid changing globals as hidden inputs.
ShadowingA parameter or local name can hide a global. Assignment makes a name local even on the right-hand side, which can cause UnboundLocalError.
ConstantsFixed global values are allowed. Name them in uppercase and keep them unchanged. Uppercase does not enforce the rule.
