Hand-Tracing

1. Hand-Tracing

Hand-tracing means following a program one statement at a time and writing down each value as it changes.

  • Start with the initialized values.
  • Evaluate the condition using the current values.
  • Record assignments in statement order.
  • Include the first false condition that ends the loop.

A trace records what Python does. It does not record what the program was supposed to do.

2. A Trace Table

A trace table has a column for each changing variable and a row for each moment: the start, each pass, and the exit. The condition column shows the test that allows each pass, so pass 1 repeats the test made at the start.

Sentinels

4. Sentinel Values

A sentinel is a special input value that marks the end of a sequence.

  • The sentinel controls the loop.
  • The sentinel is not data.
  • Test it before adding or counting the value.
  • Choose a value that cannot be valid data.

For marks from 0 to 100, -1 is safe. For temperatures, -1 is valid data and is not safe.

Two Sentinel Structures

6. Priming Reads

The input statement before a sentinel loop is a priming read. It gives the loop condition its first value.

The two reads have different moments but the same job: obtain the value for the next test.

  • The stopping condition is visible in the loop header.
  • The same input operation appears twice.

A priming-read loop is correct and often easy to trace. Its drawback is the duplicated code: if one prompt changes and the other does not, the program becomes inconsistent.

7. A Loop and a Half

while True has no exit condition in its header. break leaves the nearest loop immediately.

Sample run:

Mark (-1 to finish): 72
Mark (-1 to finish): 84
Mark (-1 to finish): -1
Values entered: 2

The input appears once. The exit test sits partway through the body, after the read, which is why this structure is called a loop and a half. Use one clear break after the read and before processing. Several hidden break statements make a loop hard to trace.

Both structures read, test, and then process only real data:

  1. read a value;
  2. test whether it is the sentinel;
  3. process it only if it is data.

Planning and Averaging

9. Storyboards

A storyboard is a written sample of the prompts, user responses, and final output.

Mark (-1 to finish): 72
Mark (-1 to finish): 84
Mark (-1 to finish): -1
Average of 2 marks: 78.00

It answers questions about the prompt, sentinel, output format, and boundary behaviour before the loop is written. For example:

  • Does the prompt clearly state the sentinel?
  • Is the sentinel ever printed as data?
  • What appears after the final input?
  • What should happen if the sentinel is entered immediately?

A storyboard is especially valuable for loops because the same prompt may appear many times during a real run.

10. A Safe Average

An average needs both a total and a count. A sentinel loop may receive no data: the user can enter the sentinel immediately. Dividing by a count of 0 raises a ZeroDivisionError.

Sample run with data:

Mark (-1 to finish): 72
Mark (-1 to finish): 84
Mark (-1 to finish): -1
Average of 2 marks: 78.00

Sample run without data:

Mark (-1 to finish): -1
No marks were entered.

The guard tests count > 0 before division. Both possible paths produce a clear result.
