Argument styles

1. Positional arguments

In a positional call, values match parameters from left to right.

L18 matched arguments by position. Today we can also name the parameters in a call and let the function supply some default values.

2. Keyword and mixed arguments

make_label("Sale", 3, "!")
make_label(symbol="!", text="Sale", width=3)

Both calls return "!!! Sale". Keyword order can change. A keyword is the parameter's name, spelled exactly as it appears in the definition.

Positional arguments come before keywords

make_label("Sale", 3, symbol="!")
make_label("Sale", width=3, symbol="!")

Both are valid mixed calls. Python fills positional slots first, then named slots.

A positional value after a keyword causes SyntaxError:

make_label(text="Sale", 3, "!")

Giving text two values causes TypeError:

make_label("Sale", text="Deal",
           width=3, symbol="!")

3. Defaults and parameter order

Defaults supply arguments that the caller omits.

CallwidthsymbolReturned string
make_label("Sale")3"-""--- Sale"
make_label("Sale", 5)5"-""----- Sale"
make_label("Sale", symbol="*")3"*""*** Sale"

The final call replaces symbol while keeping the default width. The required text argument still needs a value.

Required parameters come before optional ones

In these definitions, put required parameters first, then parameters with defaults. A caller can supply the required values and omit optional values at the end.

Valid definition:

SyntaxError in the header:

def label(width=3, text):
    return "-" * width + text

Program structure

4. Main coordinates the program

main is an ordinary function name chosen by convention. Defining it does not run its body. The call main() starts those steps.

Main coordinates input, calculation, and output

The helper computes a result. main chooses where its input comes from and what the user sees. With input 20, to_fahrenheit returns 68.0, which main prints.

5. Definitions before calls

A function must exist when its call runs.

  1. Python defines main.
  2. Python defines cube_volume.
  3. The final line calls main.
  4. Its body calls the now-defined helper.

This prints 8. A helper can appear below main if Python reaches its definition before the call runs. Calling an undefined function raises NameError.

6. The name guard

Run directly: __name__ is "__main__".

Imported as demo: __name__ is "demo".

The guard prevents the main() call during import. Other top-level statements would still run, so keep the program's work inside functions.

Calls and frames

8. Functions calling functions

Output: 12.0

Nested calls, in time order

main waits while show_share runs. It, in turn, waits for share.

  1. main calls show_share(36, 3).
  2. show_share calls share(36, 3).
  3. share returns 12.0.
  4. show_share prints it and ends, returning None to main.

9. The call stack and frames

Each call adds a frame on top. The top frame is active. Frames below it wait for their calls to finish. The file's top-level execution sits below main.

A frame remembers values and where to resume

While share runs, the function frames are:

PositionFunctionParameter valuesState
Topsharetotal=36, people=3Active
Middleshow_sharetotal=36, people=3Waiting for share
BottommainWaiting for show_share

Each call gets its own frame, with its parameter and local values. Python also remembers where execution must continue after the call.

share is evaluating:

return total / people

show_share is paused here:

amount = share(total, people)

When the call returns, Python finishes this assignment, then runs print(amount).

Returns remove frames in reverse order

The most recent unfinished call returns first. Its frame disappears, and the frame below becomes active again.

  1. share returns 12.0.
  2. show_share resumes, prints 12.0, and returns None.
  3. main resumes.

main eventually ends too, returning control to the file's top level.

Final review

Argument styles and program structure

PositionalValues match parameters from left to right.
Keywordwidth=3 names the parameter in the call. Keywords may change order. Positional values come first, and each parameter gets one value.
Defaultdef label(text, width=3): lets a call omit width. Explicit arguments replace defaults. Required parameters come first.
main()An ordinary function that coordinates the program. Its body runs only when called. Define every helper before execution reaches its call.
Guardif __name__ == "__main__": followed by an indented main() starts the program when run directly and skips that call on import.

File layout: imports, constants, helpers, main, then the guard.

Calls, frames, and tracebacks

Call stackThe unfinished calls, with the current call on top. A new call adds a frame. Its caller pauses.
FrameKeeps the call's parameter and local values. Python remembers where the caller should resume. Each call gets a fresh frame.
ReturnGives a value to the caller and removes the current frame. The caller continues at its paused call. Reaching the end returns None.
TracebackLists the path from the file's top level to the failing function. The most recent call appears last, just above the error message.
Reading an errorRead the final error type and message, then the failing source line. Work upward through callers to find where the wrong value or decision entered. The cause may be earlier than the failure.
