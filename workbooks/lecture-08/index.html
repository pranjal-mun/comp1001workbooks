1. Why programs need decisions

Programs often need to behave differently in different situations. A store may charge shipping for a small order but offer free shipping for a larger order. A program makes this choice by testing a condition.

Condition

A condition is an expression whose value is either True or False.

So far, our programs have followed one straight path. Every statement ran from top to bottom. A decision creates two possible paths. Python chooses a path from the condition's value.

The first message runs because temperature < 18 is True. The final message is outside the decision, so it always runs.

2. The six stages for a decision problem

The same problem-solving stages used for straight-line programs still apply. A decision adds a branch during design and an extra responsibility during testing.

  1. Understand: State the different situations in clear sentences.
  2. Decompose: Separate steps that always happen from steps that depend on the situation.
  3. Find patterns: Look for a threshold, category, or validity rule.
  4. Design: Write the decision as a yes/no question and show both paths.
  5. Implement: Translate the design into Python.
  6. Reflect: Test every path, especially values at the boundary.
Worked problem: a shipping charge

Problem: An order ships free when its total is at least $50. Otherwise, shipping costs $8.

  • Understand: there are two cases, free shipping and paid shipping.
  • Decompose: read the total, choose a charge, then print the charge.
  • Find patterns: the choice uses the $50 threshold.
  • Design: ask, “Is the total at least $50?”
  • Implement: use if and else.
  • Reflect: test a total below $50, exactly $50, and above $50.

3. The shape of an if statement

An if statement has a header and an indented body.

if total >= 50:
    shipping = 0

The four required parts are:

  • the keyword if;
  • a condition;
  • a colon : at the end of the header; and
  • an indented block below the header.

The body runs only when the condition is True. If the condition is False, Python skips the body and continues after the block.

4. Indentation creates a block

A block is a group of statements that belong together. Python uses indentation to show where a block begins and ends. In this course, indent each level by four spaces.

Both indented statements belong to the if. The unindented final statement is outside the block and always runs. Moving a line by four spaces can change the program's meaning even when Python reports no error.

5. else handles the other case

Use else when exactly one action should run for a False condition.

Exactly one branch runs. The else header has no condition because it means “in every remaining case.” It ends with a colon and lines up with if.

The value 50 belongs in the free-shipping branch because the condition uses >= rather than >.

6. A decision as a flowchart

A flowchart shows the order of program steps. A rectangle shows a task. A diamond shows a condition with a Yes path and a No path. Arrows show the direction of execution.

The two branches rejoin before the final output. This makes an important design idea visible: choose the value inside the branches, then do the shared work once after the branches.

7. Put shared work after the branches

Avoid repeating the same statement in both branches.

The calculation and print call are outside the branches because they happen in both cases. Keeping shared work in one place makes code easier to read and change.

9. Recognize two common syntax errors

The colon is part of the if and else syntax. Omitting it causes a SyntaxError. Run this listing to see the error Python reports.

Python reports an error similar to:

SyntaxError: expected ':'

The body must be indented. A missing or inconsistent indent causes an IndentationError.

Python reports an error similar to:

IndentationError: expected an indented block

Use four spaces for each indentation level. Configure your editor to insert spaces when you press the Tab key so that tabs and spaces are not mixed.

Read the order total.

Print the shipping charge and final total.

Coding checklist

Before you consider a decision program complete, check that:

  • the condition asks the intended yes/no question;
  • the colon is present;
  • each branch is indented by four spaces;
  • else lines up with if;
  • shared work appears once after the branches; and
  • you tested below, at, and above the boundary.
