The try statement

5. The try-except statement

The try-except statement lets a program handle an exception instead of terminating. Consider a program that reads an age.

  • The try block contains the code that might raise an exception.
  • If a ValueError is raised in the try block, control jumps to the except block.
  • After the except block, execution continues with the statement that follows the try-except. The failed statement is not executed again.

Python executes the try block in order. An exception skips the rest of the block.

7. Unhandled exceptions

An except block handles only the type that it names. Consider:

Input 0:

Traceback (most recent call last):
  ...
ZeroDivisionError: division by zero

The input 0 raises a ZeroDivisionError. The except block names only ValueError, so the exception is unhandled and the program terminates.

To handle both errors, the program needs a second except block.

Multiple except blocks

8. Multiple except blocks and their order

A try block can have one except block for each kind of exception. This program divides 100 by the value at a position.

InputOutput
025.0
oneNot a whole number.
5No such position.
1The value is 0.

Each kind of failure produces its own message. At most one except block is executed.

Python checks the except blocks from top to bottom and executes the first one that matches. This works like an if-elif chain.

The remaining except blocks are skipped.

10. The exception object

In except ValueError as err, the name err is bound to the exception object.

print(err) prints the message stored in the exception.

The message is useful to a programmer. A user is better served by a plain instruction, such as “Enter a whole number.”

12. Bare except and broad handlers

An except with no exception type is called a bare except. It handles every kind of exception.

Input 3:

Enter a whole number.

The user typed a whole number, yet the program asks for one. The real problem is a NameError, because the name prise is not defined.

A bare except also handles the exception that is raised when the user presses Ctrl+C. The user then cannot easily stop the program.

Without the except block, the traceback would name the error and the line that caused it.

An except block that names a broad type also handles errors that come from bugs in the program.

A NameError usually means a misspelled name. It should be fixed, not handled.

Review

The try-except statement

try:
    # statements that might fail
except ValueError:
    # runs for a ValueError
except (IndexError, TypeError) as err:
    # runs for either type
    # print(err) shows the message
# execution continues here

How it runs

  1. Python executes the try block in order.
  2. No exception: Python skips every except block.
  3. Exception: Python skips the rest of the try block. It executes the first except block that matches.
  4. No match: the program stops with a traceback.
  5. Execution then continues after the try-except.

Traceback: the last line gives the type of the exception and its message.

ErrorWhat you see
Syntax errorThe program does not start.
Runtime errorAn exception and a traceback.
Logic errorA wrong result and no message.

Common exceptions and good practice

CodeException
int("hello")ValueError
int("12.5")ValueError
10 / 0, 7 % 0ZeroDivisionError
[1, 2][5]IndexError
"a" + 1, len(42)TypeError
open("nope.txt")FileNotFoundError
misspelled nameNameError

Do

  • Keep the try block small.
  • Name the specific types that you expect.
  • Tell the user what to do. print(err) is for programmers.
  • Use try-except when the operation is the best test, as for int(text).

Do not

  • Use a bare except. It handles every exception, including Ctrl+C.
  • Handle a NameError or a TypeError from your own code. Fix it.
