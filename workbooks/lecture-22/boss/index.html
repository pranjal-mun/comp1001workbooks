How bosses work

These problems use recursion from Lectures 21 and 22:

  • a base case that stops the calls
  • output printed before or after the smaller call
  • helpers that carry their progress in parameters
  • several recursive choices joined with or

They use only what Lectures 4 to 22 covered:

  • input() with int() and float()
  • arithmetic, comparisons, and if statements
  • strings, indexing, and slicing
  • functions and recursion

Each problem lists the rules its checker enforces. A program that prints the right answer but breaks a rule does not pass. Check also calls your functions directly with more values and compares what they return or print. Term tests and the final exam have questions of this kind, and you write the code in PyLab there as well.

Every problem reads its values with a plain input() that shows no prompt, so the output is only what your program prints. Check runs your program several times and types a different sequence of answers each time. Every run must print exactly what the examples show.

Defeat a boss and its marker on the workbooks page is crossed off.

Press ▶ Run to try your program and Check to fight the boss. The bosses get harder from 👹 to 🐉 and are worth 10, 15, and 20 XP.

👹 Boss 1: Twelve days of shop supplies

Write show_song(days) and the supporting functions below. A song has one verse for each day of a twelve-day delivery. A verse has a heading and the supplies delivered that day. It includes the new gift and every gift from earlier days. The functions print the song and return no useful value.

Follow these rules:

  • Print verses in increasing day order, from day 1 through days.
  • Begin each verse with Day followed by its day number.
  • Print that day's gift first, followed by earlier gifts in decreasing day order.
  • Print each gift on its own line, using the wording in the table.
  • Do not print blank lines between verses.
  • Each gift's text must appear only once in your Python code.

Write these functions:

  1. show_gift(day) prints just the gift for that day. Use an if/elif chain.
  2. show_gifts(day) recursively prints the gifts for one verse.
  3. show_verse(day) prints one heading and calls show_gifts.
  4. show_song(days) recursively prints every required verse.
  5. main() reads the number of days and calls show_song.

  • show_gifts and show_song each call themselves. show_verse calls show_gifts, and main calls show_song.
  • Use no loops, lists, or dictionaries.
  • Check also calls each function directly with days from 1 to 12 and compares what it prints.
  • End the file with the standard guard.

👾 Boss 2: Encode repeated letters

Write encode(text) and a recursive helper. The function takes a string and returns its run-length encoding as a string. A run is a group of consecutive copies of the same character. Run-length encoding replaces each run with its letter followed by its length.

Follow these rules:

  • Preserve the order of the runs.
  • Include every run length, including 1.
  • Write lengths with ordinary decimal digits. A length may need more than one digit.
  • Treat uppercase and lowercase letters as different characters.
  • Return "" for empty input.
  • The encoding functions return strings and do not print.

Write these functions:

  1. run_length(text, index, count) returns the length of the first run in nonempty text. It starts with index = 0 and count = 0. The parameters track the next position to check and the number of matching letters already checked.
  2. encode(text) uses the helper and recursion to encode the full string.
  3. main() reads one line and prints Encoded: followed by the encoded string in double quotation marks.
Example 1
Input:
AAAAAAAAAAAABBBBAAAAAAB
Output:
Encoded: "A12B4A6B1"
Explanation:
The run lengths are 12, 4, 6, and 1, in that order.
Example 2
Input:
(blank line)
Output:
Encoded: ""
Explanation:
The empty string has no runs.
Constraints
  • The input has 0 through 80 English letters.
  • Use all three required functions and the standard guard.
  • Use recursion in both run_length and encode.
  • Pass the count through helper calls. Do not store it outside the function.
  • Use no loops, lists, or dictionaries.
TypedOutput
AAAAAAAAAAAABBBBAAAAAABEncoded: "A12B4A6B1"
a blank lineEncoded: ""
AEncoded: "A1"
AaAAEncoded: "A1a1A2"
80 copies of zEncoded: "z80"
MississippiEncoded: "M1i1s2i1s2i1p2i1"
Rules the checker enforces
  • Define run_length(text, index, count), encode(text), and main().
  • run_length and encode each call themselves, and encode calls run_length.
  • Both encoding functions return strings or numbers and print nothing. Check also calls them directly with other text.
  • Keep the count in parameters: do not use global, and assign no variables at the top level.
  • Use no loops, lists, or dictionaries.
  • End the file with the standard guard.

🐉 Boss 3: Exact coin total

Write possible_change(dollars, coins) and a recursive helper. The function returns whether a dollar amount can be formed using exactly the stated number of coins. Return a Boolean value.

Follow these rules:

  • A quarter is worth 25 cents.
  • A dime is worth 10 cents.
  • A nickel is worth 5 cents.
  • A penny is worth 1 cent.
  • Any number of each coin type is available.
  • Use exactly coins coins. Do not leave any unused.
  • Zero dollars can be formed with zero coins.
  • Zero dollars cannot be formed with a positive number of coins.
  • A positive amount cannot be formed with zero coins.

Write these functions:

  1. possible_change(dollars, coins) converts dollars to integer cents with int(round(dollars * 100)). It returns the helper's answer.
  2. change_helper(cents, coins) returns whether the remaining amount can use exactly the remaining number of coins. Each recursive choice tries one of the four coin types.
  3. main() reads dollars, then a coin count, on separate lines. It prints Possible: followed by the Boolean answer.
Example 1
Input:
1.00
4
Output:
Possible: True
Explanation:
Four quarters have a total value of one dollar.
Example 2
Input:
1.00
5
Output:
Possible: False
Explanation:
No choice of exactly five allowed coins totals one dollar.
Example 3
Input:
0.00
0
Output:
Possible: True
Explanation:
Using no coins forms an amount of zero.
Constraints
  • The dollar amount is from 0.00 through 2.00, with at most two decimal places.
  • The coin count is an integer from 0 through 8.
  • Use the three required functions and the standard guard.
  • Use integer cents in every helper call.
  • Join the four recursive choices with or.
  • Stop impossible branches before making more calls.
  • Use no loops, lists, or dictionaries.

Rules the checker enforces
  • Define possible_change(dollars, coins), change_helper(cents, coins), and main().
  • possible_change converts with round and returns the answer from change_helper.
  • Join four calls to change_helper with or.
  • Check watches every call to change_helper. Each one gets an integer number of cents. A call with negative cents or no coins left returns without calling change_helper again.
  • Both functions return True or False. Check also calls them directly with other amounts and coin counts.
  • Use no loops, lists, or dictionaries.
  • End the file with the standard guard.
