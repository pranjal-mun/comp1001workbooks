Tracing recursion and recursive helpers

Learning outcomes

Trace what runs before a recursive call and what waits until it returns. Use helpers to carry the part of a problem that still needs checking.

Reading: §11.2 and §11.3

  • Trace recursive calls, printed output, and returned values.
  • Count recursion depth as the number of unfinished calls.
  • Read a recursive traceback and identify common recursion bugs.
  • Write a palindrome helper that carries two indices.
  • Trace sentence checks that skip nonletters and ignore letter case.
  • Combine the answers from two recursive calls.
  • Test inputs near the stopping points.

Depth and errors

2. Recursion depth

factorial(n) returns the product from 1 to n. It returns 1 for 0. Assume n is a nonnegative integer.

Here, depth counts only the factorial calls. The maximum depth is 4. For factorial(n), the maximum depth is n + 1 with this base case.

3. Reading errors and checking progress

countdown(n) is meant to print down to 1. This version repeats the same input. Read the last traceback line first. Find the repeated call.

def countdown(n):
    if n == 0:
        return
    print(n)
    countdown(n)

countdown(3)
Traceback (most recent call last):
  File "countdown.py", line 7, in <module>
    countdown(3)
  ...
  File "countdown.py", line 5, in countdown
    countdown(n)
  [Previous line repeated 996 more times]
RecursionError: maximum recursion depth exceeded

This is a traceback excerpt. Python groups repeated entries. Counts vary. A very large valid input can also exceed Python's depth limit.

countdown(n) should print the positive integers from n down to 1. Assume n is a nonnegative integer. The first version is buggy. The second version corrects the recursive argument.

The buggy version repeats 3, 3, 3, .... The correction reaches 0. A base case helps only when the calls can reach it.

4. Base answers and missing returns

product(n) should return 1 × 2 × ⋯ × n. For n = 0, it should return 1. The calls stop, but the result is wrong. The zero travels back through every multiplication.

The base case must return 1. Also check reachability. Subtracting 2 from an odd input will skip 0.

total(n) should return 1 + 2 + ⋯ + n. It should return 0 for 0. Assume n is a nonnegative integer. The first version discards the smaller answer. The second version uses it.

Calling a function produces an answer. The caller must use that answer. A function that reaches its end without return returns None.

total(n) is meant to return the sum from 1 to n. This version loses the answer.

Palindrome helpers

5. Palindrome helpers and stopping cases

is_palindrome(text) returns True when the text reads the same backward. Start with words made of lowercase letters. "racecar" is a palindrome. "robot" is not. After checking the outside pair, the same question applies to the inside.

is_palindrome(text) checks the whole word. palindrome_helper(text, start, end) checks only the part between two indices. The caller supplies just the word. The wrapper supplies the starting indices. The helper changes the indices on later calls.

Both function definitions must run before the first call. The text stays the same. The unchecked part gets smaller.

The helper checks the characters from start to end, including both ends.

  1. If start >= end, return True.
  2. Otherwise, if the outside characters differ, return False.
  3. Otherwise, call the helper with start + 1 and end - 1.

An empty word starts with start = 0, end = -1. Check start >= end before indexing the text.

Checkpoint 2

The wrapper calls the helper with 0 and len(text) - 1. For "abba", the index pairs are (0, 3), (1, 2), and (2, 1). The expected results are True, False, and True.

7. Skipping nonletters

sentence_helper(text, start, end) checks a selected part of a sentence. It ignores letter case and skips nonletters. isalpha() tests whether a character is a letter. lower() converts a letter to lowercase. Every recursive branch moves at least one index inward.

Call sentence_helper(text, 0, len(text) - 1) to check the whole sentence. "A man, a plan, a canal, Panama!" returns True.

Two recursive calls

8. Two recursive calls

fib(n) returns Fibonacci number n, with fib(0) = 0 and fib(1) = 1. Each later number is the sum of the previous two. Assume n is a nonnegative integer. Python finishes the left call before starting the right call. The calls run in sequence. The parent combines both returned values.

fib(n) returns Fibonacci number n. Each nonbase call adds two smaller answers.

Call numberCallDepthReturned value
1fib(3)11 + 1 = 2

3fib(1)31
4fib(0)30
5fib(1)21

The return order is calls 3, 4, 2, 5, then 1. There are five calls in total. At most three Fibonacci calls are unfinished at once.

Checkpoint 3

Write a recursive function ways(n). It returns the number of ways to climb n stairs using steps of size 1 or 2.

  • Assume n is a nonnegative integer.
  • Return 1 for n = 0 and n = 1.
  • Use two recursive calls for larger inputs.
  • Check 0, 2, and 3.

For 3 stairs, the possible step sequences are:

  • 1 + 1 + 1
  • 1 + 2
  • 2 + 1

Split the possibilities by the size of the first step. For zero stairs, doing nothing counts as one way.

Rules the checker enforces

  • Use two recursive calls and no loop.
  • Check calls ways with 0, 2, and 3, and with every n from 1 to 12.

3. Smallest letter

Write smallest_letter(text). It returns the alphabetically smallest letter in a nonempty word of lowercase English letters. Compare letters with <. Use one recursive call and no sorting function.

  • smallest_letter("m") returns "m".
  • smallest_letter("cabin") returns "a".
  • smallest_letter("zoo") returns "o".
Rules the checker enforces
  • Define smallest_letter(text) with one parameter. It returns one letter.
  • Use one recursive call and no loop.
  • Compare letters with <. Do not use sorted, sort, min, or max.
  • Check calls it with the three words above and with other words such as "banana" and "za".

4. Lowercase a selected range

Write lowercase_part(text, start, end) and lowercase_text(text). The helper returns the characters from start through end as lowercase text in their original order. The wrapper returns the lowercase version of the whole string.

  • The helper returns "" when start > end.
  • Otherwise, both indices are valid positions in text.
  • Use lower() on one character at a time.
  • Use one recursive call in the helper.
  • Do not use lower() on the whole string or on a slice.

Check these calls:

  • lowercase_part("AB-CD", 1, 3) returns "b-c".
  • lowercase_text("Shop!") returns "shop!".
  • lowercase_text("") returns "".
Rules the checker enforces
  • Define lowercase_part(text, start, end) and lowercase_text(text). Both return strings.
  • Use one recursive call in the helper and no loop.
  • lowercase_text calls lowercase_part for the whole string.
  • Use lower() only on one indexed character, such as text[start].lower().
  • Check makes the three calls above and also tries other strings and ranges.

5. Multiply by halving

Write multiply(a, b). It returns the product of two nonnegative integers. Use addition to build the answer. Do not use multiplication, division with /, or a loop.

Use these mathematical rules:

  • Multiplying by zero gives zero.
  • For even b, find the product with b // 2, then add that answer to itself.
  • For odd b, double the product with b // 2, then add a.
  • Use one recursive call in each nonbase call.

Check these calls:

  • multiply(7, 0) returns 0.
  • multiply(7, 4) returns 28.
  • multiply(7, 5) returns 35.
Rules the checker enforces
  • Define multiply(a, b) with two parameters. It returns the product.
  • Use one recursive call and no loop.
  • Do not use * or / anywhere in your code.
  • Check makes the three calls above and also tries pairs such as (12, 13) and (9, 1000).

Final review

Calls, output and errors

ConceptRule to remember
Print before the callRuns while calls go deeper.
Print after the callWaits until the smaller call finishes.
Recursion depthCounts unfinished calls along one active path. State which functions you count.
Recursive tracebackRead the error type first. Find the repeated call site. Check the input change.
RecursionErrorThe call depth exceeded Python's limit. Check progress and the stopping condition. A very large valid input can also reach the limit.
No progressChange the input toward a reachable base case.
Wrong base answerChoose a value that makes the next larger case correct.
Missing returnPass the smaller answer back, or combine it and return the result. Reaching the function's end returns None.

Helpers and branching calls

ConceptRule to remember
Wrapper functionSupplies the helper's starting state from the caller's input.
Helper parametersTrack the unchecked part. A palindrome helper uses start and end.
Palindrome successReturn True when start >= end. Check before indexing.
Palindrome mismatchReturn False when the outside letters differ.
Palindrome progressMove both indices inward after a match. For sentences, use lower() to compare letters. Use isalpha() to skip nonletters.
Two recursive callsFinish the first call before the second. The parent uses both answers.
Call number and depthNumber records entry order. Depth counts unfinished calls on the current path.
Combining answersFibonacci adds two earlier numbers. Stairs adds counts for two possible first steps.
