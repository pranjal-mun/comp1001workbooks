How bosses work

These problems use the list operations from Lecture 24:

  • indexes, len, and index assignment
  • append, insert, pop, remove, and del
  • in tests, slices, and separate copies

They use only what Lectures 4 to 24 covered:

  • input() with int(), and blank input lines
  • strings and .split()
  • while and for loops, range, and if statements
  • lists and the list operations above

Each problem is a script: write the statements at the top level, with no functions. Each problem lists the rules its checker enforces. A program that prints the right answer but breaks a rule does not pass. Term tests and the final exam have questions of this kind, and you write the code in PyLab there as well.

Every problem reads its values with a plain input() that shows no prompt, so the output is only what your program prints. Check runs your program several times and types a different sequence of answers each time. Every run must print exactly what the examples show.

Boss 4 also asks you to compare the sieve with an earlier method. That part is under the code box. Check grades only the program.

Defeat a boss and its marker on the workbooks page is crossed off.

Press ▶ Run to try your program and Check to fight the boss. The bosses get harder from 👹 to 💀 and are worth 10, 15, 20, and 25 XP.

👹 Boss 1: Latest reading first

Write a program that stores integer sensor readings until the user enters -999. A sentinel is a value that ends input and is not stored. Print the readings from the last entered to the first entered.

  • Read one integer per line.
  • Keep repeated readings.
  • Print Readings: before the readings.
  • Print each reading on its own line.
  • If there are no readings, print No readings after the heading.
Example 1
Input:
18
-4
18
-999
Output:
Readings:
18
-4
18
Explanation:
The sentinel is not stored. Repeated readings stay in the list.
Example 2
Input:
-999
Output:
Readings:
No readings
Explanation:
The first input is the sentinel, so the list is empty.
Constraints
  • Every input line is an integer from -999 through 999.
  • Use -999 only as the sentinel.
  • Store readings in one list with append.
  • Display the stored readings with an index loop from the end.
  • Write a script. Do not use reverse or a slice with a step.
TypedOutput
18, -4, 18, -999Readings:, 18, -4, 18
-999Readings:, No readings
5, -999Readings:, 5
999, -998, 0, -999Readings:, 0, -998, 999
1 to 6, then -999Readings:, then 6 down to 1
7, 7, 7, -999Readings:, 7, 7, 7
Rules the checker enforces
  • Write a script. Do not define functions with def.
  • Store the readings in one list with append.
  • Display the readings with an index loop from the end, such as range(len(readings) - 1, -1, -1).
  • Do not use reverse, reversed, or a slice with a step.

👾 Boss 2: One entry per word

Write a program that collects words for a shop's label list. Read one word per line until a blank line. Print each word once, in the order of its first appearance.

  • A blank line contains no characters and ends input.
  • Treat uppercase and lowercase letters as different characters.
  • Print Words: before the words.
  • Print each kept word on its own line.
  • If no words were entered, print No words after the heading.
Example 1
Input:
rice
tea
rice
salt
tea
(blank line)
Output:
Words:
rice
tea
salt
Explanation:
The second rice and the second tea add no new entries.
Example 2
Input:
(blank line)
Output:
Words:
No words
Explanation:
A blank first line leaves the list empty.
Constraints
  • Each nonblank input is one word containing only English letters.
  • Use one list and an in test before append.
  • Keep the first appearance order.
  • Write a script.

To enter the blank line, press Enter without typing anything.

  • Write a script. Do not define functions with def.
  • Use one list. Do not use dictionaries or sets.
  • Test whether the word is already in the list with in or not in before append.
  • Keep each new word with append.

🐉 Boss 3: Manage a waiting list

Write a program that manages a shop's waiting list. Start with waiting = ["Mia", "Noor"]. Keep a separate copy of this starting list before reading commands. Read one command per line until a blank line. A name is one word. Repeated names are allowed.

Use these commands:

CommandRequired action
add nameAdd the name at the end with append.
front nameAdd the name at index 0 with insert.
serveRemove the first name with pop. Print Served: and that name.
cancel nameRemove the first matching name with remove.
drop iDelete the name at nonnegative index i with del.
next nPrint a slice containing up to the first n names as a Python list.

Follow these rules:

  • For serve on an empty list, print Empty list.
  • For cancel with an absent name, print Name absent.
  • For drop with an invalid index, print Invalid index.
  • A failed command leaves the list unchanged.
  • Successful add, front, cancel, and drop commands print nothing.
  • At the end, print Starting: and the saved list on one line.
  • Then print Final: and the current list on one line.
Example 1
Input:
add Ivo
front Uma
serve
cancel Noor
drop 1
next 3
(blank line)
Output:
Served: Uma
['Mia']
Starting: ['Mia', 'Noor']
Final: ['Mia']
Explanation:
The saved list keeps both starting names after the current list changes.
Example 2
Input:
(blank line)
Output:
Starting: ['Mia', 'Noor']
Final: ['Mia', 'Noor']
Explanation:
No commands change the starting list.
Example 3
Input:
serve
serve
serve
cancel Mia
drop 0
next 2
(blank line)
Output:
Served: Mia
Served: Noor
Empty list
Name absent
Invalid index
[]
Starting: ['Mia', 'Noor']
Final: []
Explanation:
The last four commands leave the empty list unchanged.
Constraints
  • Every command has exactly the format shown in the command table.
  • Each name contains only English letters and no spaces.
  • The values i and n are nonnegative integers.
  • Use one current list and one separate starting copy.
  • Use the required list method or statement for each command.
  • Use a slice for next. You may use .split() to read commands.
  • Write a script. Check absent names and invalid indexes before changing the list.

The examples are the first three rows. Each command is typed on its own line, and the last line is blank.

Rules the checker enforces
  • Write a script. Do not define functions with def.
  • Use append for add, insert for front, pop for serve, and remove for cancel.
  • Use del for drop, such as del waiting[i].
  • Use a slice for next, such as waiting[:n].

💀 Boss 4: Cross out composite numbers

Write a program that reads an integer limit and prints every prime number up to that limit. A prime is an integer greater than 1 with no positive divisors except 1 and itself. A composite number is an integer greater than 1 that is not prime. Use the Sieve of Eratosthenes, which crosses out multiples of prime candidates.

Follow these rules:

  • Build a list containing the integers from 0 through the limit.
  • Keep each number at the index equal to that number.
  • Cross out 0 and 1 before selecting candidates.
  • Cross out a number by replacing its element with 0.
  • Do not remove elements, because each index must keep its meaning.
  • Select candidates from numbers that have not been crossed out.
  • Cross out each candidate's larger multiples. Keep the candidate itself.
  • Print Primes:, then each remaining prime on its own line.
Example 1
Input:
18
Output:
Primes:
2
3
5
7
11
13
17
Explanation:
The remaining nonzero elements greater than 1 are prime.
Example 2
Input:
2
Output:
Primes:
2
Explanation:
The smallest allowed limit includes just one prime.
Constraints
  • The limit is an integer from 2 through 10,000.
  • Build the list with append in a loop.
  • Use index assignment to cross out numbers.
  • Use range with a step to visit multiples.
  • Write a script.
TypedOutput
18Primes:, 2, 3, 5, 7, 11, 13, 17
2Primes:, 2
3Primes:, 2, 3
10Primes:, 2, 3, 5, 7
49Primes:, then the 15 primes from 2 to 47
100Primes:, then the 25 primes from 2 to 97
10000Primes:, then the 1,229 primes from 2 to 9973
Rules the checker enforces
  • Write a script. Do not define functions with def.
  • Build the list of numbers with append in a loop.
  • Cross out a number by replacing its element with 0, such as values[multiple] = 0.
  • Visit the multiples with range and a step, such as range(p * p, limit + 1, p).
  • Do not remove elements with remove, pop, or del.
  • Do not test divisors with %.
