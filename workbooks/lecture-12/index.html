The while Loop

1. Why Loops

A loop repeats a block of statements.

Loops are useful when:

  • the same kind of work happens several times;
  • the number of repetitions is not known in advance;
  • values must be totalled or counted; or
  • work continues until a condition changes.

Without a loop, printing the numbers 1 through 5 would require five separate statements. A while loop expresses the repeated action once.

The indented statements are the loop body. One complete execution of the body is an iteration, also called a pass.

2. The while Statement

A while statement has a Boolean condition, a colon, and an indented body.

while condition:
    statement
    statement

The counting loop from section 1 is a while statement:

count = 1
while count <= 5:
    print(count)
    count = count + 1

Python follows this cycle:

  1. Test the condition.
  2. If it is True, run the body.
  3. Return to the test.
  4. Stop when it is False.

The condition means keep going while this is true. It does not mean stop when this becomes true.

The loop continues while the balance is below the target. It stops as soon as balance < target becomes False.

Designing a Loop

3. Spot Repetition

Problem statements often describe a loop without using the word loop. Look for words such as repeat, each, every, until, keep going, total, and count.

Consider this problem:

An investment starts at $100 and grows by 50 percent each year. Report how many years it takes to reach at least $200.

The phrase each year until the balance reaches $200 describes repetition. The exact number of years is not known before the program starts, so a condition must decide when to stop.

4. Initialization, Test, and Update

A useful while loop has three connected parts.

PartPurposeCounting example
InitializeGive the loop variable its first valuecount = 1
TestDecide whether another iteration should runcount <= 5
UpdateMove the loop toward a false conditioncount = count + 1

Initialization happens once, before the loop. The test happens before every possible iteration. The update normally happens inside the body.

Each part can cause a different problem:

  • missing initialization can cause a NameError;
  • a wrong test can cause an off-by-one error;
  • a missing or wrong update can cause an infinite loop.

Loop Boundaries and Errors

6. Zero Iterations

A while loop tests before its first iteration. If the condition starts as False, the body does not run.

Only Finished is printed. Results needed after the loop must be initialized before the test.

This is a zero-iteration loop. It is not automatically an error. Sometimes there is no work to do.

7. Infinite Loops

An infinite loop keeps running because its condition never becomes False.

Missing update. This example has no update:

count = 1
while count <= 5:
    print(count)

The program prints 1 repeatedly. The value of count never changes, so the condition stays true.

Wrong direction. An update can also move away from a false test:

count = 5
while count > 0:
    print(count)
    count = count + 1

Here count grows, so it never becomes 0.

Press Ctrl+C to interrupt a program that does not stop. Then compare the test with every possible update. Each path through the body must move the program toward a false test.

Totals, Counts, and Input

9. Accumulators

An accumulator stores a result that grows during a loop.

Start a sum at 0. Start a product at 1. Initialize once, before the loop.

If total = 0 were inside the body, every iteration would erase the earlier work. Starting a product at 0 would make every later product 0.

A counter increases by 1 when an event occurs. It counts items rather than adding their values.

number controls the loop. evens records a fact about the values. The update to number runs on every iteration.

The investment problem combines the six stages, a target-controlled loop, an accumulator-like balance, a counter, and boundary testing. For the investment program:

  1. state the constants and starting values;
  2. identify one year's repeated calculation;
  3. test whether the balance is still below the target;
  4. update both the balance and the year; and
  5. report the result once after the loop.

Test three cases:

  • the starting balance is below the target;
  • the starting balance equals the target;
  • one update reaches the target exactly.
