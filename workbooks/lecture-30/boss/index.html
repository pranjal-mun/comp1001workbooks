How bosses work

These problems use functions that raise exceptions and callers that handle them:

  • raise with a built-in exception type and a message
  • try statements with except, else, and finally
  • an exception that passes from a function to its caller

They use only what Lectures 4 to 30 covered:

  • input() with int() and float(), and a blank line that ends the input
  • f-strings such as :.2f, and the string methods split and strip
  • if tests, while and for loops, lists, the list method index, and functions

Each problem lists the rules its checker enforces. A program that prints the right answer but breaks a rule does not pass. Term tests and the final exam have questions of this kind, and you write the code in PyLab there as well.

Every problem reads its values with a plain input() that shows no prompt, so the output is only what your program prints. Check runs your program several times and types a different sequence of answers each time. Every run must print exactly what the table shows. The checker also calls your functions directly, so each function must raise the exceptions that the problem names.

Defeat a boss and its marker on the workbooks page is crossed off.

Press ▶ Run to try your program and Check to fight the boss. The bosses get harder from 👹 to 💀 and are worth 10, 15, 20, and 25 XP.

👹 Boss 1: Average or nothing

Write a program that reads numbers until a blank line and prints their average. Rewrite the starter function so it raises an exception when there are no values.

  • The function never prints. Its docstring lists ValueError("no values") for an empty list.
  • The caller handles the exception and prints No average: and the message.
  • When the call succeeds, print Average: and the value with two decimal places in an else block.
Example 1
Input:
4
8
(blank line)
Output:
Average: 6.00
Explanation:
The average of 4 and 8 is 6.
Example 2
Input:
-1
(blank line)
Output:
Average: -1.00
Explanation:
<code>-1</code> is a valid average.
Example 3
Input:
(blank line)
Output:
No average: no values
Explanation:
The list is empty.
Constraints
  • Every non-blank line is a valid number for float.
  • Read the lines with a plain input() that shows no prompt.
  • Raise and handle ValueError. Use try, except, and else. Use no bare except.

👾 Boss 2: Reduce a fraction

Write a program that reads two whole numbers on separate lines and prints the reduced fraction.

  • Write gcd(a, b) using Euclid's algorithm for non-negative numbers.
  • Write reduce_fraction(top, bottom). Return the reduced fraction as a string.
  • Raise ValueError("denominator must not be zero") when the denominator is zero.
  • Move a negative sign to the top. A top of zero gives "0/1".
  • Print Enter whole numbers. if conversion fails. Print Error: and the message if the function raises.
  • Use separate try blocks. Both errors have type ValueError, but the caller gives them different messages.
Example 1
Input:
18
-24
Output:
-3/4
Explanation:
The sign moves to the numerator.
Example 2
Input:
0
9
Output:
0/1
Explanation:
Zero has the required reduced form.
Example 3
Input:
4
0
Output:
Error: denominator must not be zero
Explanation:
The function raises an exception.
Constraints
  • Read two lines with plain input() calls that show no prompt. Each line can contain text.
  • Raise ValueError for a zero denominator. Handle ValueError in both callers. Use no bare except.
  • Use a while loop in gcd. Return a string from reduce_fraction.

🐉 Boss 3: Proper divisors and perfect numbers

Write a program that reads lines until a blank line. For each line, report whether its number is perfect.

  • A proper divisor is positive, divides the number evenly, and is smaller than the number.
  • proper_divisors(n) returns the list of proper divisors. If n < 1, it raises ValueError("n must be at least 1").
  • is_perfect(n) returns whether the sum of the proper divisors equals n. Let the exception pass to its caller.
  • Print the number followed by is perfect or is not perfect. Print the input and the error message for an invalid value.
  • Use separate small try blocks for conversion and for the call. Put the call in the conversion's else block.
Example 1
Input:
6
8
(blank line)
Output:
6 is perfect
8 is not perfect
Explanation:
The proper divisors of 6 are 1, 2, and 3. Their sum is 6.
Example 2
Input:
0
abc
(blank line)
Output:
0: n must be at least 1
abc: not a whole number
Explanation:
Zero is outside the contract. The text cannot be converted.
Constraints
  • Each line can contain text. A blank line ends input. Use a plain input() that shows no prompt.
  • Raise and handle ValueError. Use no bare except.
  • Keep both functions and the program in one file. Use an if __name__ == "__main__": guard.

  • is_perfect has no try, so the exception passes to its caller.
  • Put the main program under if __name__ == "__main__": and use at least two try statements.
  • Do not use a bare except or except Exception.

💀 Boss 4: Order lines

Write a program that reads order lines until a blank line. It prints the result of each line and a final total. Use the parallel lists in the starter code.

  • A line contains an item and a quantity separated by a comma. Strip spaces around each part.
  • parse_quantity(text) converts the text with int. Raise ValueError("quantity must be at least 1") for a value below 1.
  • line_cost(line) raises ValueError("expected item,quantity") unless there are exactly two parts.
  • If the item is absent, raise ValueError("unknown item " + item). Otherwise return its price times the quantity.
  • The caller prints Rejected: and the exception message when a line fails.
  • On success, add the cost to the total and print Added and the cost with two decimal places.
  • After each line, print Checked: and the original line. At the end, print Total: and the total with two decimal places.
Example 1
Input:
pen,2
cup, 1
(blank line)
Output:
Added 3.00
Checked: pen,2
Added 4.25
Checked: cup, 1
Total: 7.25
Explanation:
Both costs are added to the total.
Example 2
Input:
pen,0
(blank line)
Output:
Rejected: quantity must be at least 1
Checked: pen,0
Total: 0.00
Explanation:
Zero is outside the quantity contract.
Constraints
  • Each input line can contain text. A blank line ends input. Use a plain input() that shows no prompt.
  • Raise and handle ValueError. Use try, except, else, and finally. Use no bare except.
  • Let the ValueError from int pass to the caller when a quantity is text such as two.
