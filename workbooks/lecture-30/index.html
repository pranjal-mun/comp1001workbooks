2. Two sides of a function call

The docstring is a contract between a function and the code that calls it. The writer checks the arguments and raises an exception when the function cannot do its job. The caller passes valid arguments and handles an exception where it knows how to respond.

5. Choosing an exception type

Use the built-in exception type that matches the problem. The message should state the requirement that was not met.

ProblemTypeExample
The argument has the wrong typeTypeErrorwithdraw(500, "100")
The value is not acceptableValueErrorwithdraw(500, -50)
A position is outside the sequenceIndexError[1, 2][5]
No other built-in type fitsRuntimeError

A TypeError usually means that the calling code is wrong. A ValueError often comes from data, such as an amount that a user typed. A message such as "bad input" does not tell the caller what to change. "amount must be positive" does.

7. A bad value or a bug

An exception does not always mean that someone made a mistake. A request for more than the balance is a normal event.

What happenedExampleResponse
Valid argumentswithdraw(500, 100) returns 400None needed
A value the function cannot acceptwithdraw(500, 900) raises ValueErrorThe caller handles it and tells the user
An argument of the wrong typewithdraw(500, "100") raises TypeErrorFix the calling code
A bug in the functionAn exception that the docstring does not list, such as NameError, or a wrong resultFix the function

Handle an exception when the program can respond to it while it runs, such as a bad value from a user. Do not handle an exception that shows a bug. The traceback shows where to fix the code.

13. An unhandled exception passes to the caller

When a function raises an exception and does not handle it, Python ends that function and passes the exception to its caller. Each caller gets a chance to handle the exception. If no caller handles it, the program stops and Python prints the traceback.

Review

The function writer

def withdraw(balance, amount):
    if amount > balance:
        raise ValueError("amount is too large")
    return balance - amount
  • List the raised exceptions in the docstring.
  • Check the arguments. Raise an exception when the function cannot do its job.
  • TypeError: wrong type. ValueError: unacceptable value.
  • Do not print an error and return a special value.

The caller

try:
    balance = withdraw(balance, amount)
except ValueError as err:
    print("Cannot withdraw:", err)
  • Pass arguments that meet the docstring.
  • Handle a listed exception where you know how to respond.
  • Put only the call that can fail in the try block.
  • Do not handle an exception that shows a bug. Fix the code.
  • Do not continue with a made-up value.

The try statement

try:
    # code that might fail
except ValueError as err:
    # a ValueError was raised
else:
    # no exception was raised
finally:
    # always executed, last
# execution continues here
BlockWhen it is executed
exceptA matching exception
elseNo exception
finallyAlways, last

How it runs

  1. Python executes the try block.
  2. No exception: the else block, then the finally block.
  3. A matching exception: that except block, then the finally block.
  4. No match: the finally block, then the exception passes to the caller.

Reading a traceback

  1. Last line: the type and the message.
  2. Entry above it: where it was raised.
  3. Entries above that: the calls that led there, one frame each.
