3. The selection sort algorithm and function

Selection sort puts a list of length n in ascending order. It changes the input list.

  1. For each position i from 0 to n - 2, do steps 2 to 4.
  2. Set smallest to i.
  3. For each index j from i + 1 to n - 1: if values[j] is less than values[smallest], set smallest to j.
  4. Swap the values at i and smallest.

After step 4, the positions from 0 to i contain the smallest values in order.

After n - 1 passes, the last value is in place. A list of length 0 or 1 needs no passes.

The function selection_sort follows these steps.

After each comparison, advance the index of the list that supplied the value. The result is [1, 2, 4, 6, 8].

merge takes two ascending lists and returns a new ascending list.

i and j identify the next unused values. The loop runs while both indices are valid.

If the values are equal, the function takes the left value first.

When the loop ends, the two slices contain the unused values. At most one slice has elements.

Merge sort

7. Merge sort splits and combines

The function calls itself on each half. A list of length 0 or 1 is already in order.

The upper branches show splits. The lower branches show merges.

Merge sort, step by step: split until each part has length 1. Then merge each pair of sorted parts.

merge_sort returns a new ascending list. It keeps the input list unchanged.

The base case returns a copy of a list of length 0 or 1.

values[:mid] and values[mid:] cover separate parts of the list.

Each recursive call sorts one part. merge combines the two results after both calls return.

For an odd length, the right part has one extra element.

10. Big O: how the time requirements grow

Big O describes how the work of an algorithm grows when the input grows.

The letter n is the size of the input. For a sort or a search, n is the length of the list.

To find the Big O of an algorithm:

  1. Count the steps, for example the value comparisons.
  2. Keep only the term that grows fastest.
  3. Remove the constant factor.

Selection sort makes n(n − 1) / 2 = ½n2 − ½n comparisons. The fastest term is ½n2. Remove the ½. Selection sort is O(n2).

Big O does not give the time in seconds. It shows how the time changes when n becomes large.

Each program below counts its steps for a list length of n = 8.

One loop over n values: O(n)

A loop inside a loop: O(n2)

The inner loop runs n times for each pass of the outer loop. That gives n × n = n2 steps.

Two loops one after the other give n + n = 2n steps. That is still O(n).

A loop that halves n: O(log n)

Each pass halves n: 8, 4, 2, 1. The loop runs 3 times. For n = 1024, the loop runs 10 times.

The number of passes is about log2 n. This loop is O(log n).

Binary search halves the search range after each check. Binary search is O(log n).

Merge sort has about log2 n levels. Each level writes all n elements once. That gives n log2 n steps, so merge sort is O(n log n).

AlgorithmBig OReasonSteps for n = 1,024
Binary searchO(log n)Halves the range10

The step counts use log2 n, n, n log2 n and n2. A real program does a different number of steps. Big O shows the growth.

When n doubles:

  • O(log n) work grows by one step.
  • O(n) work doubles.
  • O(n2) work becomes four times as large.

A lower curve means less work. For large lists, merge sort is much faster than selection sort, because n log n grows much more slowly than n2.

Merge two sorted lists

  • Compare the first unused value in each list.
  • Append the smaller value. Advance only its index.
  • For equal values, take the left value first (<=).
  • When one list is used up, extend the result with the rest.
  • A merge of m elements makes at most m − 1 comparisons.
