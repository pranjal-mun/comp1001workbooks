4. Maximum and Minimum

To find an extreme, store the best value seen so far. Update it only when a better value appears. For nonempty data, initialize from the first real item rather than from 0.

Starting largest = 0 is unsafe when all values could be negative. Zero might not be part of the data, yet it would incorrectly remain the largest. The first real value is a valid starting answer. Before using digits[0], check that the sequence is not empty.

5. Search for the First Match

A search can use a position initialized to -1. The value -1 means "not found" because it is outside the valid index range.

The loop stops at the first match. If no character matches, the assignment inside the if never runs and the result remains -1.

6. Last Match and a Special First Pass

To find the last match, do not stop at the first one. Scan every position and replace the recorded position whenever another match appears.

The same sentinel result -1 handles an absent target. A break would be wrong here because a later match may replace the current answer.

Sometimes one pass needs special handling. Printing separators is a common example: a separator belongs between items, not before the first one.

The Boolean variable starts as True and changes permanently after the first pass. Later passes use the else branch.

7. Comparing Adjacent Items

Two items are adjacent when they are next to each other. To compare the current item with the preceding one, remember the previous item.

The first item initializes previous. The loop starts at position 1 because position 0 has no item before it. The final assignment prepares for the next comparison. For empty data, check the length before reading index 0.

8. The Random Module

A simulation uses a program to imitate a process. Many simulations need unpredictable choices. Python's random module provides pseudorandom values: they behave unpredictably, but they are produced by a repeatable calculation.

CallResult
random.randint(a, b)a whole number from a through b, inclusive
random.random()a decimal from 0.0 up to, but not including, 1.0
random.choice(sequence)one item from a nonempty sequence

Unlike range, randint includes its upper endpoint. A simulated six-sided die therefore uses random.randint(1, 6).

9. Random Seeds

The random generator has an internal state. random.seed(value) puts it into a known starting state. The same seed followed by the same calls produces the same sequence.

Seeding is useful while debugging because a failure can be reproduced. Change or remove the fixed seed when the finished program should behave differently on each run. A seed does not make one outcome more or less likely. It only chooses a repeatable starting point in the pseudorandom sequence.

10. Simulation

Suppose two dice are rolled. One trial is easy: generate two integers from 1 through 6 and test whether their sum is 7. A loop repeats that trial many times.

The exact probability is 6 out of 36, or about 0.1667. A simulation does not have to match it exactly. With many trials, the estimate will usually be close. Different unseeded runs produce slightly different estimates.

11. Solve a Simpler Problem First

When a loop problem feels too large, solve a smaller version that preserves the important idea. For the dice simulation, a useful sequence is:

  1. Generate and print one die value.
  2. Generate and print two die values.
  3. Test whether one pair sums to 7.
  4. Repeat that test a small number of times.
  5. Count the hits.
  6. Increase the number of trials and calculate the estimate.

Each step is a small extension of working code. The solution to the simpler problem often becomes the body of the final loop.

We will build a short simulation in stages. The goal is to estimate how often a random digit is greater than the digit before it.

Next, keep the first digit as previous. Each loop pass generates one new digit, tests one adjacent pair, and updates previous.
