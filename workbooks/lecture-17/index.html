Functions

1. You have been calling functions since day one

Your first Python program already used a function: print("Hello World"). The function name is print, and the argument is the string "Hello World". The parentheses call print with that string. Python runs the function, and the screen shows Hello World.

Someone wrote the code behind print. We have been using it without reading all of that code. So far, we have learned how to use functions. Today, we learn how to write our own.

2. A function gives a task a name

A function is a named sequence of instructions that performs a task. For make_coffee(), the instructions are to grind the beans, brew the coffee, and pour into a cup. The name lets us refer to the whole task at once. Calling the function means asking it to carry out those instructions. The same idea works for a greeting, a calculation, or a report.

3. A function as a black box

In round(6.8275, 2), the arguments are 6.8275 and 2, and the result is 6.83. To use round, we need its specification: give it a number and a number of decimal places, and it returns the rounded value. We can use that promise without knowing its internal steps. Arguments are values supplied by the program. They can come from variables or literals as well as user input.

Decomposition

8. Decomposition and the six stages

Suppose a program must display an event notice. Give each function one job: show_heading() displays the title, show_details() displays the time and place, and show_reminder() displays what to bring. The caller puts the pieces in order. We can understand the overall plan before writing each body.

The calls read like the plan for the notice. Each function names one job and can be tested separately. If another notice needs the same heading, call show_heading() again.

1. UnderstandThe notice must show a title, time and place, and a reminder.
2. DecomposeGive the heading, details, and reminder separate jobs.
3. Find patternsEach job uses familiar print statements.
4. DesignName the functions and decide their call order. Check that each required line appears once.
5. ImplementWrite the function bodies and the calls in Python.
6. ReflectTest each function, then the whole notice. Check the wording and order against the requirements.

If a piece becomes hard to describe, revisit the decomposition.

Final review

Function definitions and calls

A function is a named sequence of instructions. Its body can contain assignments, input, decisions, and loops.

  • def creates the function. Use a colon and an indented body. Names follow the rules for variable names.
  • A call runs the body, then execution continues after the call.
  • Define the function before calling it. Each new call runs the body again.
  • Put the docstring first in the body to describe what the function does.

Design, documentation, and testing

Function boundariesGive each function one clear job. A useful name, repeated work, or a separate test can justify a function.
Black-box interfaceKnow the function's task and how to call it. The implementation can stay hidden.
DocumentationPut the docstring first in the body. Describe the function's promise. help(function_name) shows it.
TestsPredict the results before running. Test each function separately, then test the complete program. Check ordinary inputs and boundaries.
Decisions and loopsif/elif/else selects one branch. A loop repeats its body. Keep statements that should run once outside the loop.
Cases worth checkingFibonacci: counts 0, 1, and several. Middle characters: empty, odd length, and even length. Check the empty string before indexing.

Understand, decompose, find patterns, design and check, implement, reflect. Revisit an earlier stage when a test exposes a problem.
